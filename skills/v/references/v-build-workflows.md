# /v Build Workflows — Bug Fix / Feature Tiny-Small / Feature Medium-Large

This file holds the full step-by-step build workflows referenced from `/v` SKILL.md Step 3.

## Bug Fix Workflow

1. **Isolate (MANDATORY — W25-F25 / W-conc-fix; not "parallel mode only").** Run these substeps IN ORDER after `git worktree add`. **Skipping (b) or (c) is the documented cause of "facade root not set" / namespace-mangled tests / silent workflow-verification degradation** (3 of 4 PHP /v sessions 2026-05-27/28 hit this when an orchestrator improvised `ln -s vendor` instead of running (b)).
   - **(a) Create-or-adopt the worktree (C4 — external path; A-2 adopt-or-create, HANDOFF_orchestrator-hardening-3.md):** Never call `git worktree add` directly — a compaction/fork-restart re-running this step with the SAME `CLAUDE_SESSION_ID` but a DRIFTED `{slug}` (free text chosen from the task, not deterministic) must ADOPT the worktree it already created, never mint a second one (repro + fix pinned by `v-worktree-adopt-or-create-test.sh`). Call the shared helper — it scans `git worktree list` for a `.claude-session-lock` already carrying this SID and adopts it (refreshing the lock's pid + the compat symlink + the C5 active-session marker), or creates fresh exactly as before when none exists (external path from `WORKTREES_EXTERNAL_BASE`, output by v-bootstrap.sh, to eliminate the Pest `P\worktrees\fix\...` namespace collision — S2 incident): ```bash _wt_out="$(bash "${CLAUDE_SKILL_DIR:-$HOME/.claude/skills/v}/references/v-worktree-adopt-or-create.sh" fix "{slug}" "$CLAUDE_SESSION_ID" "$REPO_ROOT")"; _wt_rc=$?; eval "$_wt_out"; { [ "$_wt_rc" -eq 0 ] && [ -n "${WORKTREE_ABS_PATH:-}" ]; } || echo "FATAL: worktree adopt-or-create failed (rc=$_wt_rc)" >&2```. `WORKTREE_ABS_PATH`, `WORKTREE_ADOPTED` (true|false), and `WORKTREE_BRANCH` are now set. **If the FATAL line printed (rc≠0 or empty `WORKTREE_ABS_PATH`) do NOT proceed — an empty prefix collapses "worktree paths" onto main (the exact contamination isolation exists to prevent); apply the BROKEN WORKTREE protocol (repair → recreate → `BLOCKED_<sid>.md`), never fall back to main. EXCEPTION rc=7 (W71-F11 duplicate-task guard): another session already has an UNMERGED branch for this exact task slug — do NOT repair/recreate and do NOT self-override; STOP, report the duplicate dispatch in your completion, and write `BLOCKED_<sid>.md` citing the sibling branch the guard printed (`V_DUP_TASK_OK=1` only on an explicit user instruction).** Switch ALL subsequent file paths to the absolute worktree path (`$WORKTREE_ABS_PATH`). At session end (Step 6.5 merge-back), clean up the active marker: `rm -f "$HOME/.claude/runtime/active-worktree-${CLAUDE_SESSION_ID}" "$HOME/.claude/runtime/v-session-claim-${CLAUDE_SESSION_ID}"` (the start-claim is removed alongside the active-worktree marker so a just-finished worktree session — transcript still fresh — does not show as a live parallel sibling for ~45 min; FP-MED2. Inline sessions have no merge-back step, so their claim ages out via the 8h GC instead).
   - **(b) PHP vendor (Laravel/PHP only) — MANDATORY:** `bash ~/.claude/hooks/worktree-php-setup.sh "$WORKTREE_ABS_PATH"`. CoW-clones main's `vendor/` (`cp -c` APFS / `cp --reflink=auto` Linux — near-instant, ~0 extra disk) so the worktree gets its own REAL vendor + `composer dump-autoload`. Idempotent; self-corrects a pre-existing plain or split symlink. ⚠️ **Do NOT `ln -s vendor` or rely on the `WorktreeCreate` event hook** — that event does NOT fire on Bash `git worktree add` (settings.json has no PostToolUse Bash trigger), and a symlinked `vendor/bin/pest` runs MAIN's autoloader → `Cannot redeclare class ComposerAutoloaderInit<lock-hash>` FATAL or (worse) silently tests main's code (PHP `__DIR__` resolves through symlinks, php.net #46260; proven with composer repro 2026-05-27).
   - **(c) App `.env` + concurrency isolation — MANDATORY:** `bash ~/.claude/hooks/worktree-app-setup.sh "$WORKTREE_ABS_PATH"`. Copies main's `.env` (worktrees don't inherit it — without this the app can't boot → Step 3.5 workflow verification silently DEGRADES to unit tests, observed 2026-05-27), applies per-worktree `CACHE_PREFIX`/`REDIS_PREFIX`/sqlite-DB isolation, creates Laravel storage dirs. Idempotent, fail-open, refuses to touch main's `.env`.
   - **(d) Node `node_modules` (if needed):** manually symlink — `ln -s "$REPO_ROOT/node_modules" "$WORKTREE_ABS_PATH/node_modules"` (or `npm install` if a manifest touched).
   - **Do NOT skip for solo sessions** — the runner is NOT guaranteed sequential; a concurrent `/v` against the same repo may start at any time, and inline-on-main would then tangle both sessions (observed 2026-05-25). Isolation is unconditional for non-Maintenance work.
2. **Investigate** — read error context, trace the issue
3. **TDD regression test** — invoke `/v-tdd` (Skill tool) to create failing tests before the fix. v-tdd merges the RED set from any of: `WORKFLOW_BLAST_RADIUS_<sid>.md` `states_to_verify` (Step 1.6), `IMPACT_MAP_<sid>.md` `tests_to_add` (Step 1.8 — cross-subsystem consumers: reporting, cache, integrity, async, emails, authz), and `ASYNC_LIFECYCLE_TRACE` `failure_modes_to_test`. The fix must make ALL pass, not just the reported symptom. `browser_only_states` / `browser_to_verify` go to the Step 3.5 verifier, not v-tdd. For frontend-only bugs with no backend-testable entries, write a failing test manually or rely on the verifier's committed spec.
4. **Fix** — address the root cause and ALL blast-radius `states_to_verify`; do not expand beyond the traced flow + its shared dependencies
5. **Verify** — test passes, no regressions in related tests
6. **Polish + UX critique + Workflow verification (MANDATORY for UI sessions)** — run UI Change Detection (per `/v` Step 3.5); if UI files changed: (a) invoke `/v-polish`, (b) dispatch UX critique via the `v-dispatch-subagent.sh` subprocess helper (`--agent v-ux-critique-reviewer`) per Step 3.5 W48-F2 → `UX_CRITIQUE_<sid>.md`, (c) dispatch browser workflow verification via the `v-dispatch-subagent.sh` subprocess helper (`--agent v-workflow-verifier`) per Step 3.5 → `WORKFLOW_VERIFICATION_<sid>.md`. The Stop hook `check-review-artifact.sh` blocks completion if `UX_CRITIQUE_<sid>.md` is missing/invalid OR `WORKFLOW_VERIFICATION_<sid>.md` is missing / `status: fail` (`degraded` accepted). Remediate `status: fail` WF-* findings before pre-flight.
7. **Quality gates** — invoke `/v-pre-flight` (Agent tool, model: haiku)
8. **Agent review** — Dispatch agents per `/v` Step 5
9. **Fix agent findings** — Remediate ALL ACCEPT/MODIFY verdicts in **one consolidated pass**, then re-invoke `/v-pre-flight` **once**. Do NOT run pre-flight after each individual finding fix — batch all fixes first, then run one final pre-flight. Exception: if a finding fix expands the touched-surface delta to a subsystem not covered by the original pre-flight (new file types, new routes, new jobs), run one additional scoped pre-flight for only the expanded surface.
10. **Convention check** — invoke `/v-verify-done` (Agent tool, model: haiku for scoped/small diffs; sonnet recommended for full-mode or >30 changed files — see /v § Verify-Done Model Tiering. Production `enforce-haiku-dispatch.sh` hook currently auto-corrects to haiku; tiering becomes active once the hook is updated to honor `VERIFY_DONE_MODEL_OVERRIDE` env var.)
11. **QA Acceptance & Remediation Loop (Step 6.4.9 — MANDATORY when production code changed)** — dispatch `v-qa-reviewer` via the `v-dispatch-subagent.sh` subprocess helper; run the SME-analysis → fix → re-test loop (cap 3 iterations); converge to `QA_REPORT_<sid>.md` `verdict: pass`, or escalate via `BLOCKED_<sid>.md`. (Step 1.8 produced `IMPACT_MAP_<sid>.md` pre-implementation; Step 6.2.6 reconciles it against the actual diff.) The Stop hook blocks completion without a passing (or escalated+BLOCKED) `QA_REPORT` + `IMPACT_MAP`.
12. **Merge back** — handled by /v Step 6.5 Mandatory Merge-Back Gate (parallel-safe; do NOT manually invoke `git merge` here). Step 6.5 runs the canonical merge-back script with per-project flock, idempotency, and conflict-fallback to WORKTREE_HANDOFF.
